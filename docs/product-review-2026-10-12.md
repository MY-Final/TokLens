## 第一批：采集可靠性与数据可信度

### 1. 让用户直接知道数据读自哪里、为什么没有统计

- 已确认：Codex `default_root()` 只使用 USERPROFILE，不支持 HOME / CODEX_HOME；macOS 默认环境无法得到根目录，自定义目录也不会被采用。
- 已确认：数据源页只有静态默认路径说明；没有实际解析目录、目录可访问状态和最近请求时间。存在历史会话时可能显示“已连接”，不足以证明本次发现来源。
- 已确认：“最近扫描”来自 source_files.last_scan_ms，Codex 未变化文件会跳过写入，因此它更接近最近导入时间。
- 建议：尊重客户端配置路径并支持平台 home；展示实际扫描路径、上次检查 / 导入时间、最近请求时间；区分已停用、来源不存在、读取失败、部分未解析、有会话但无用量。
- 建议：提供单客户端重扫，以及可预览后复制的脱敏诊断摘要，只含版本、计数、错误类别与时间，不含正文、凭据或默认完整路径。手动目录覆盖作为后续能力单独设计。
- 定位：`src-tauri/src/collectors/codex/sync.rs`、`src-tauri/src/usage/analytics/records.rs`、`src/pages/SourcesPage.tsx`。
- 验收：Windows / macOS / 自定义 home 合成环境；目录不存在、权限失败、空目录、历史数据仍在但源已移除；清晰说明正在使用的路径。

### 2. 同步完成后更新数字，切换筛选时保持标题与数据一致

- 已确认：useDataSourceStatus 的完成事件只替换 sync 状态，不重查 clients / firstEventMs 等；短于两秒的同步可能完全错过进行中轮询。
- 已确认：后台同步不会增加 refreshToken。滚动日期会在分钟变化时重查，但固定自定义区间没有这个触发条件。
- 已确认：useAsyncData 对任何 key 变化保留旧 data，并且不暴露 refreshing；请求总览把新的 range / selectedRange 与旧结果一起渲染，会话列表也可能把新客户端筛选与旧列表一起显示。分析页已将数据和范围标签绑定，可作为参考。
- 建议：区分“同一筛选刷新”与“切换筛选”。同一筛选平滑更新；切换筛选时明确更新状态，或保留与旧结果对应的范围标签。同步完成只使相关查询失效，不重置滚动、页码、图表视图。
- 定位：`src/hooks/use-data-source-status.ts`、`src/hooks/use-async-data.ts`、`src/components/RequestActivityView.tsx`、`src/pages/SessionsPage.tsx`。
- 验收：瞬时同步、首次启动同步、固定自定义范围、快速连续切换、请求乱序 / 失败 / 重试；各处数字和数据时间一致。

### 3. 统一“零、未知、部分已知”的展示

- 已确认：会话累计总览的今日 / 区间 Token 直接展示后端已知求和；全部会话总量未知时仍显示 0。客户端分布也会显示 0 Token / 0%。
- 已确认：会话状态提示把 NULL 总量解释为“客户端记录里没有 Token 计数”，但解析失败也可能造成 NULL；partial 提示只解释分页 / 续接，未覆盖无法证明完整度的情况。
- 已确认：会话累计页缓存命中率由前端分别汇总的字段相除，未像请求分析那样约束为 input / cache_read 成对已知的样本。缺失字段时容易产生误导。
- 建议：没有记录显示“未记录”，有记录但总量全部未知显示“—”，混合显示“已知部分”；来源未核实时使用“尚未导入可用用量”，提供前往数据源检查入口。缓存比率统一后端口径。
- 定位：`src/pages/OverviewPage.tsx`、`src/components/ClientUsageCard.tsx`、`src/components/SessionTable.tsx`。
- 验收：空集合、实测零、全未知、部分未知、部分缓存字段缺失；总览、排行、浮框和会话列表语义一致。

### 4. 增强正在写入的日志与失败重试处理

- 代码风险：Codex 读取行失败时保留部分解析结果并返回成功；同步随后覆盖该文件明细，并把扫描前文件长度写入水位。文件随后未变化时，下一轮可能直接跳过，不能保证注释所称的重试。
- 建议：区分永久损坏行、未完成尾行与 I/O 失败；不以部分读取结果替换已知完整明细，失败不推进成功水位，提交前校验文件指纹。
- 定位：`src-tauri/src/collectors/codex/parser.rs`、`src-tauri/src/collectors/codex/sync.rs`、`src-tauri/src/usage/store/import.rs`。
- 验收：注入读取错误、半行、追加、截断、替换；保留已有统计并能在后续完整读取时恢复。

## 第二批：让信息更容易找到

### 5. 会话列表可翻页、可定位，并与总览连通

- 已确认：前端固定最多 200 个会话，没有翻页；后端及 API 已支持 offset。
- 已确认：默认按请求时间的总览与按会话开始时间过滤的会话列表归属不同。昨天开始、今天继续的会话会贡献今日请求，但不出现在今日开始的会话列表。
- 建议：提供分页、项目 / 模型 / 会话 ID 搜索和排序；明确“区间有请求的会话”与“区间开始的会话”。点击总览日期 / 客户端、分析项目可携带筛选进入明细，并可返回原位置。
- 建议：跨页面保留当前统计模式、客户端筛选和已选图表视图；不要让导航把用户刚选的视图重置。
- 验收：超过 200 个会话、跨日续聊、空结果、分页末尾、返回导航和切换范围；不采集会话正文作为搜索数据。

### 6. 总览更贴近日常问题

- 建议：优先展示“今天用了多少、主要用哪个客户端、数据更新到什么时候”；选择今天时按小时展示趋势，长范围继续按日展示。
- 建议：增加有限的可解释比较，例如截至当前时刻相对昨天同期的差异；两段覆盖不足时明确标记，不把未记录当作下降。
- 建议：快捷范围补“昨天”，保持时间控件与标题共用工具栏；细分选项通过浮层收纳，避免继续增加整行工具栏。
- 小窗口与键盘交互需要桌面验收，再决定是否调整当前布局，不仅凭浏览器错误页下结论。

## 后续候选

- **时间兼容**：当前共享解析只支持 UTC Z 且最多三位小数；补支持明确时区偏移与微秒 / 纳秒、严格日历日期校验。会话累计日桶仍固定 24 小时，建议与请求模式共用本地日历边界以支持夏令时。需补合成测试并记录口径影响。
- **归档历史**：Codex 只发现 sessions 目录，首次导入前已经归档的会话不会进入统计。支持 archived_sessions 前先设计跨目录迁移及重复记录处理。
- **请求级模型**：Codex 解析器读取 turn_context.model，但归一化请求 model 始终为空；分析按会话主模型归因。可逐请求保存当时模型，无法判定时保持未知，并说明历史重解析影响。
- **更新体验**：下载进度换成 MB，增加取消下载和失败后打开官方 Release 的入口；按版本记住“稍后提醒”，降低重复提示。仍保持用户触发联网、签名验证和明确安装动作。
- **性能**：先测量大历史库的扫描耗时、内存峰值、查询延迟与空闲占用。Claude 任一转录变化会重读全量，Codex 活跃文件会整文件重解析；依据测量结果决定增量解析或查询合并，不先引入缓存架构。
