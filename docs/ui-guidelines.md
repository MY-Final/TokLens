# UI/UX 设计规范

TokLens 是长时间驻留的桌面工具型应用：界面应安静、克制、信息密度优先，让数据本身成为视觉焦点。
风格基调：**简洁、现代、以白色与中性色为主**，不使用装饰性效果。

## 1. 设计原则

1. **内容优先**：先结构（标题、筛选、数据）再装饰；任何视觉效果都不能影响读数的准确性。
2. **克制**：一个页面只保留一个视觉重点；不做多余的卡片、渐层、阴影、动效。
3. **一致**：颜色、间距、圆角、图表配色来自统一 token；同类信息在全局使用同一种呈现方式。
4. **可信**：实测与估算数据在视觉上必须可区分，单位与时间范围必须可见（见第 6 节与 `data-metrics.md`）。
5. **桌面优先**：窗口默认 1000×700，最小 800×600；不为移动端做适配，但小窗口下主内容不得溢出或错位。

## 2. 颜色与主题

- 只使用 `src/index.css` 中定义的语义 token（通过 Tailwind 类使用）：
  `background` / `foreground` / `card` / `popover` / `primary` / `secondary` / `muted` / `accent` / `destructive` /
  `border` / `input` / `ring` / `sidebar*` / `chart-1..5`。
- **禁止**在组件里写死颜色（`bg-white`、`text-neutral-500`、`#fff`、`rgb(...)`、内联 `style` 色值）；
  例外只有 `src/index.css` 的 token 定义本身。
- 暗色模式通过 `.dark` 覆盖 token 实现，组件内不得写"暗色分支"逻辑。
- 强调色用于主操作与选中态，保持稀缺；大面积区域使用 `background` / `muted` 这类中性底色。

## 3. 层次、间距、圆角、字体

| 维度 | 规则                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------- |
| 层次 | 优先用 1px 边框（`border`）+ 背景色差 + 间距分层；阴影只用于浮层（dialog/popover/dropdown/sheet）                   |
| 间距 | 使用 Tailwind 4px 网格（`gap-2/3/4/6`），同一列表项内间距一致，不要出现 `13px` 之类的散值                           |
| 圆角 | 由 `--radius` 派生：容器 `rounded-lg`、控件 `rounded-md`、标签/徽标 `rounded-sm` 或全圆                             |
| 字号 | 正文 `text-sm`；标题 `text-base`/`text-lg`；辅助信息 `text-xs` + `muted-foreground`；不要使用 `text-2xl` 以上做装饰 |
| 数字 | 表格与指标使用 `tabular-nums`；ID、模型名、路径等用等宽字体                                                         |
| 动效 | 仅用于状态反馈，时长 ≤ 200ms；不使用装饰性动画                                                                      |

## 4. 布局

- 主框架：左侧导航（`sidebar`）+ 右侧内容区；导航项保持在 7 个以内，超出请重新分组。
- 页面结构：页面标题 + 时间范围/筛选条 + 主内容（表格、图表、明细），主内容优先铺满可用宽度。
- 卡片只用于承载"一组相关指标"，同一视图内卡片不超过 3 个，且**禁止卡片嵌套卡片**。
- 列表与表格是主要呈现方式，避免用大量小卡片堆叠替代表格。
- 三态必须实现：加载用 `skeleton`，空数据用空状态文案（说明"没有数据"与"如何产生数据"），
  错误用内联提示（`text-destructive`）+ 可重试操作，不要用原生 `alert`。

## 5. 组件使用

- 优先使用已存在的 shadcn/ui 组件（`button`、`input`、`select`、`table`、`tabs`、`dialog`、`alert-dialog`、
  `dropdown-menu`、`popover`、`tooltip`、`badge`、`progress`、`scroll-area`、`separator`、`skeleton`、`switch`、
  `calendar`、`card`、`command`、`sheet`、`sidebar`、`sonner`）与 `lucide-react` 图标。
- **不要引入新的 UI 组件库或图标库**（antd、MUI、Chakra、Element、其他图标集等）。缺少组件时按 shadcn 方式补充：
  `pnpm dlx shadcn@latest add <component>`，并把生成文件视为 vendor 代码（不手改、不加入 `eslint.config.js` 的强规则范围）。
- `src/components/ui/**` 与 `src/hooks/use-mobile.ts` 是生成物：需要调整外观时优先在业务组件里组合 Tailwind 类，
  而不是修改生成文件；确需修改时必须在提交说明中写明原因。
- 图标默认 `size-4`（16px），图标按钮必须有 `aria-label` 或 `tooltip`，禁止用 emoji 代替图标。
- 所有可交互元素必须提供 `hover` / `focus-visible` / `disabled` 状态，键盘可达（Tab 顺序符合阅读顺序）。
- 通知统一使用 `sonner`，不要在页面内自建 toast。

## 6. 数据可视化（recharts）

- 图表必须包含：指标名称、单位、时间范围；无数据时显示空状态而不是空坐标轴。
- 颜色只能使用 `--chart-1` ~ `--chart-5`；同一指标在所有图表中使用同一颜色，客户端/模型维度配色保持稳定。
- **估算数据处理**（与 `data-metrics.md` 的 `estimated` 等级一致，必须可区分）：
  - 估算系列使用虚线或更浅的填充，并在图例、tooltip、坐标轴标注"估算"；
  - 估算值不得与实测值直接相加后作为一个数展示；需要合并展示时必须同时给出拆分；
  - 无法估算时显示 `—`，不要显示 0。
- tooltip 必须给出该数值的口径（例如"实测 token / 含缓存"）与单位；金额标注币种。
- 不使用 3D、渐变填充、装饰性动画；不引入第二套图表库。
- 图表要有标题/说明文字，避免只靠颜色传达含义（色弱可读）。

## 7. 文案与数字格式

- 界面文案使用中文；术语与 `data-metrics.md` 保持一致（会话、请求、实测、估算、缓存 token 等）。
- 大数字使用千分位；token 可缩写为 `12.3k` / `1.2M`，tooltip 给出精确值。
- 时间范围必须显式标注（如"最近 7 天"），并按本地时区聚合；跨时区场景需注明时区。
- 金额统一标注币种（当前为 USD），小于 0.01 美元显示 `<$0.01`。
- 空状态、错误文案要说明"发生了什么 + 下一步怎么做"，避免"出错了"这类无信息提示。

## 8. 无障碍

- 正文对比度 ≥ 4.5:1，辅助文字不低于 3:1；不要用纯色深浅差极小的文字。
- 表格使用语义化表头（`table` 组件），排序/筛选状态可被读屏识别。
- 不使用"仅颜色"传达状态：错误/估算/异常同时提供文字或图标。

## 9. 反模式（禁止）

- 玻璃拟态、霓虹渐变、大面积彩色背景、随机阴影、装饰性发光。
- 卡片套卡片、每个指标一个卡片、卡片内再放表格造成多重边框。
- 硬编码颜色/间距魔数、复制粘贴的"近似样式"。
- 引入新 UI 库、新图标库、第二套图表库。
- 用动画掩盖加载延迟，或用占位内容造成布局跳动。
- 未标注的估算数据、未标注单位的图表、把估算与实测混算成一个数字。

## 10. 提交前检查

- [ ] 颜色全部来自语义 token，无硬编码色值
- [ ] 间距/圆角/字号取自统一尺度，未出现散值
- [ ] 加载、空、错误三态齐备
- [ ] 图表有单位、时间范围与图例，估算系列已标注
- [ ] 图标按钮有 `aria-label`/tooltip，键盘可达
- [ ] 未新增 UI/图表/图标库，未修改 `src/components/ui/` 生成代码
