# 数据统计规范

本文是 TokLens 统计口径的唯一事实来源。任何数字在进入界面之前，都必须能回答：
**数据从哪来、属于哪个等级、如何计算、时间范围是什么、单位是什么**。
新增或修改指标时，必须同时更新本文与 `docs/ui-guidelines.md` 中对应的展示要求。

## 1. 范围

统计对象（客户端）当前为：**Codex、Claude Code、OpenCode**，后续可扩展。
统计维度：会话、请求、token、模型、成本、时间分布、客户端与项目维度。
统计范围限于**本机会话/日志文件**，不涉及任何远端数据或账号数据。

## 2. 术语

| 术语      | 含义                                                       |
| --------- | ---------------------------------------------------------- |
| 客户端    | 产生数据的 AI 编程客户端（Codex / Claude Code / OpenCode） |
| 会话      | 客户端记录的一次对话/任务单元，具有稳定标识                |
| 事件      | 归一化后的最小统计单位，通常对应一次请求或一次响应         |
| 请求      | 一次模型调用                                               |
| token     | 模型计的输入/输出/缓存 token 计数，按类别分列，不混合求和  |
| 成本      | 依据内置价格表换算出的人民币/美元金额，当前统一为 USD      |
| measured  | 真实采集：客户端文件中直接记录的字段                       |
| derived   | 派生：由真实字段直接换算（如 token 总量 = 输入 + 输出）    |
| estimated | 估算：客户端未记录、由间接信息推算（如按字符数估算 token） |

## 3. 数据来源与等级

每个字段、每个指标都必须标注等级，规则如下：

| 等级      | 判定标准                                         | 展示要求                                 |
| --------- | ------------------------------------------------ | ---------------------------------------- |
| measured  | 直接读取客户端文件中记录的数值                   | 正常展示，可在 tooltip 标注来源文件/字段 |
| derived   | 由 measured 字段经确定性公式计算（无猜测系数）   | 正常展示，tooltip 说明计算方式           |
| estimated | 含假设或经验系数（字符数、平均长度、价格推算等） | 必须显式标注"估算"，样式上与实测区分     |

强制要求：

1. 不允许把 estimated 与 measured 相加后作为一个数字展示；需要合并时必须拆分呈现。
2. 缺失值用"缺失"表达（UI 显示 `—`），不得用 0 代替。
3. 任何估算规则必须写在本文第 7 节，并配有单测。

## 4. 归一化事件模型

跨端字段命名统一使用 `snake_case`（Rust DTO）→ 前端 `camelCase` 映射，字段含义与等级如下：

| 字段                                       | 类型               | 必需 | 等级     | 说明                                           |
| ------------------------------------------ | ------------------ | ---- | -------- | ---------------------------------------------- |
| `client`                                   | enum               | 是   | measured | `codex` / `claude_code` / `opencode`           |
| `session_id`                               | string             | 是   | measured | 客户端提供的会话标识，缺失时用文件路径哈希兜底 |
| `event_id`                                 | string             | 是   | derived  | 会话内序号/记录哈希，用于去重                  |
| `timestamp`                                | ISO 8601（含时区） | 是   | measured | 事件时间                                       |
| `model`                                    | string?            | 否   | measured | 模型标识，缺失时按"未知模型"处理               |
| `input_tokens`                             | u64?               | 否   | measured | 输入 token                                     |
| `output_tokens`                            | u64?               | 否   | measured | 输出 token                                     |
| `cache_read_tokens` / `cache_write_tokens` | u64?               | 否   | measured | 缓存读写 token，单列统计                       |
| `cost_usd`                                 | f64?               | 否   | derived  | 由模型 + token 与价格表换算                    |
| `source`                                   | enum               | 是   | -        | 该事件整体可信等级                             |
| `confidence`                               | f64?               | 否   | -        | 估算置信度（0–1），仅 estimated 事件需要       |

字段可以不落库，但含义与等级必须稳定；新增字段时在本文补一行。

## 5. 指标口径

每个指标必须同时声明五要素：**定义、单位、时间范围、来源等级、计算方式**。当前登记如下（状态为"未实现"表示尚未编码）：

| 指标                   | 单位  | 时间范围 | 等级                        | 计算方式                                                         | 状态   |
| ---------------------- | ----- | -------- | --------------------------- | ---------------------------------------------------------------- | ------ |
| 会话数                 | 个    | 选定区间 | measured                    | 去重后的 `session_id` 数量                                       | 未实现 |
| 请求数                 | 次    | 选定区间 | measured                    | 事件条数（去重后）                                               | 未实现 |
| 输入 token             | token | 选定区间 | measured                    | `input_tokens` 求和                                              | 未实现 |
| 输出 token             | token | 选定区间 | measured/estimated          | `output_tokens` 求和；缺失时按第 7 节估算                        | 未实现 |
| 缓存 token             | token | 选定区间 | measured                    | `cache_read_tokens` + `cache_write_tokens`，独立展示，不计入输入 | 未实现 |
| 成本                   | USD   | 选定区间 | derived                     | Σ(按模型与 token 类别 × 价格表单价)                              | 未实现 |
| 活跃时长               | 小时  | 选定区间 | estimated                   | 相邻事件间隔去尾求和（见第 7 节）                                | 未实现 |
| 按客户端/模型/项目分布 | %     | 选定区间 | measured（分母为 measured） | 子集指标 ÷ 同等级总量                                            | 未实现 |

口径细则：

- **去重与幂等**：唯一键为 `(client, session_id, event_id)`；重复扫描同一文件不得重复计数。
  增量扫描依据文件 `mtime` + 大小，必要时用内容哈希确认。
- **时区与边界**：按系统本地时区聚合；"今天/本周/本月"按本地日历边界计算，跨时区展示需注明时区。
- **成本与价格表**：价格表内置、本地、版本化，包含生效日期；未匹配价格的模型显示"未定价"并保持 0 成本，
  在 UI 中单独提示，不得静默按 0 处理。价格表更新视为口径变更（见第 9 节）。
- **取整与显示**：token 取整；成本保留 4 位小数，`<$0.01` 时显示 `<$0.01`；百分比保留 1 位小数。
- **缓存 token 口径**：缓存读写独立成列，不并入输入 token，也不参与"总 token"的隐式求和；
  如需给出总量，必须明确写为"输入 + 输出 + 缓存"。

## 6. 数据清洗

- 不修改原始文件：清洗只发生在内存中的归一化阶段。
- 无法解析的记录：跳过并计数，在界面显示"未识别记录 N 条"，不猜测字段含义。
- 异常时间戳（早于 2023 或晚于当前时间 + 1 天）：标记为异常并排除出统计，计数上报。
- 重复事件（同一 `event_id` 出现在多个文件）：保留首次出现，其余计入重复计数。

## 7. 估算规则（必须可追溯）

每条估算规则必须写明：适用条件、公式、系数来源、置信度、生效日期，并有单元测试。

| 编号 | 适用条件               | 公式 / 依据                                     | 置信度       | 状态   |
| ---- | ---------------------- | ----------------------------------------------- | ------------ | ------ |
| E1   | 客户端未记录输出 token | `字符数 ÷ 4`（英文为主的经验值）                | 0.5          | 未实现 |
| E2   | 客户端未记录输入 token | 同上，按提示词字符数估算                        | 0.5          | 未实现 |
| E3   | 成本换算               | 价格表单价 × token 数（价格表版本需随结果展示） | -（derived） | 未实现 |
| E4   | 活跃时长               | 事件间隔 ≤ 30 分钟的相邻事件间隔之和            | 0.7          | 未实现 |

约定：

- 估算结果必须携带 `source = estimated` 与 `confidence`。
- 估算公式变更必须更新本表并说明对历史展示的影响。
- 前端不得自行做估算，估算只在 Rust 侧完成并随 DTO 返回等级信息。

## 8. 数据质量与校验

- **对账**：每个客户端适配器上线前，抽样与客户端自身统计对比，记录差异率、差异原因（如缓存口径、时区）。
- **fixture**：解析与聚合必须有去敏 fixture 单测（`src-tauri/tests/fixtures/<client>/`），
  包含未知字段、字段缺失、空文件、异常时间戳等边界。
- **覆盖率优先项**：估算公式（E1/E2/E4）、去重逻辑、时间边界聚合必须有测试。
- **不做**：依赖真实数据目录、当前时间或网络的自动化测试。

## 9. 口径版本与变更

- 本文维护一个口径版本号，格式 `MAJOR.MINOR`，当前为 `1.0`。
- 破坏性变更（去重规则、token 计入口径、价格表来源、时区处理）升 `MAJOR`；新增指标或字段升 `MINOR`。
- 每次变更需在提交说明中记录：变更内容、原因、对历史数据展示的影响。
- 界面展示的统计需与本文版本一致；发布说明中注明本次口径版本。

## 10. 隐私与安全

默认保护本地会话隐私，以下为硬性要求：

1. **只读**：不修改、不移动、不删除客户端数据文件。
2. **不采集正文**：默认不读取、不保存、不显示消息正文；解析时只提取第 4 节的元数据字段。
3. **不落盘**：统计结果与缓存仅存元数据；除用户显式导出外，不复制原始会话文件到应用目录。
4. **无网络出口**：默认不发起任何网络请求、不上报遥测；联网能力必须由用户显式开启并登记到 `docs/architecture.md`。
5. **不写日志正文**：日志、错误信息、崩溃信息不得包含会话正文与完整用户路径。
6. **可清除**：应用数据支持一键清除；清除后不影响客户端原始数据，UI 需说明这一点。
7. **导出**：导出属于用户显式操作，导出内容默认不含会话正文，并提示文件名与保存位置。
